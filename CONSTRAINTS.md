# Technical & Operational Constraints (`CONSTRAINTS.md`)

This document defines technical boundaries, platform rules, FreeRTOS safety standards, and pinout protocols enforced across all sub-projects in `vx-binocle-espidf`.

---

## 1. Platform & Tooling Constraints

### C-01: ESP-IDF Virtual Environment Selection (`eim`)
- **Rule**: ESP-IDF build and configuration commands MUST be executed via `eim` (Espressif Installation Manager).
- **Environment Matrix**:
  - `interface_board` & `factory apps/*`: Target `master` (ESP-IDF v6.2.0) via `eim run "<cmd>" master`.
  - `left_screen` & `right_screen`: Target `v5.5.5` (ESP-IDF v5.5.5) via `eim run "<cmd>" v5.5.5`.
  - `emulator-console` & `bennu`: Ignored / excluded from build evaluation.

### C-02: Target MCU Strapping Pin Protections
- **Chip Architecture**: ESP32-S3.
- **Strapping Pins**: GPIO 0, GPIO 3, GPIO 45, GPIO 46.
- **Constraint**: Peripheral assignments (I2C, SPI, TWAI/CAN, UART, ADC) must avoid pull-up/pull-down conflicts on strapping pins during boot.

---

## 2. Hardware Pinout & Peripheral Protocol

### C-03: Pinout & Bus Speed Declarations
- Peripheral pin numbers, I2C/SPI bus speeds, and TWAI baud rates MUST be explicitly declared in header macros or `Kconfig` files.
- **Interface Board I2C Defaults**:
  - `CONFIG_I2CDEV_DEFAULT_SDA_PIN`: GPIO 3
  - `CONFIG_I2CDEV_DEFAULT_SCL_PIN`: GPIO 9
- **Display CAN/TWAI Pins**:
  - `CONFIG_CAN_TX`: GPIO 19
  - `CONFIG_CAN_RX`: GPIO 20

---

## 3. FreeRTOS Task Safety Constraints

### C-04: Task Stack Size Standards
- Minimum task stack size for tasks invoking C stdlib, formatted printing (`printf`/`ESP_LOG`), or string formatting is **4096 bytes** (4KB).
- `CONFIG_FREERTOS_TIMER_TASK_STACK_DEPTH`: 4096 bytes.
- `CONFIG_FREERTOS_HZ`: 1000Hz (1ms tick).

---

## 4. Software Architecture & Parity Constraints

### C-05: Non-Factory Screen File Parity Across `main/` Directory
- No screen-specific branch variations are allowed inside any file within `left_screen/main/` vs `right_screen/main/`.
- All files under `main/` MUST maintain 100% byte-for-byte content parity (`diff -r left_screen/main right_screen/main` must return 0 diffs).
- Any logic differences between left and right displays must be guarded by `#ifdef CONFIG_LEFT_SIDE_DISPLAY` / `#else` / `#ifdef CONFIG_RIGHT_SIDE_DISPLAY`.
- `components/ui` files generated by EEZ Studio are exempt from this restriction.
